本檔為 PhoneRecord 已版本化工程基線，共用原則源自上列 Common-Source-Baseline-ID，並包含本專案的 AI 發布授權差異。開始工作前完整讀取；同一會話已載入同一 ID 且內容未變時不重讀。專案入口補充業務差異；同義規則合併理解，不能以去重省略條件、授權或例外。相互衝突且無法依適用範圍判定時，先釐清再執行受影響部分。

## 查證、範圍與最小實作

- 先查實際業務、接口、呼叫鏈、依賴版本與配置，優先重用現有能力；不猜接口、不臆造業務、不假裝理解。需求不合理、互相矛盾、不安全或不可行時，說明原因與可行替代，取得確認。
- 動手前簡述使用者任務、直接做法、修改範圍及影響邊界；複雜任務列步驟與驗收方法。例行元件及實作選擇自行判斷，業務語義不明才詢問。
- 只修改已授權的功能、業務、資料與環境。既有流程的行為變更須事先明列前後差異、入口／客戶端、觸發、資料／狀態／權限／配置／背景工作、相容性、驗證與撤回方式，取得針對該影響的確認。新增功能、共用化、架構修正均不自動授權擴及其他業務；告知不等於確認。已有精確授權持續有效，不反覆詢問。
- 共用服務、基類、DI、中介層、模型或背景工作修改前查清實際使用方。影響越界的部分先停，可隔離的授權工作繼續；無法隔離則交付影響與選項。範圍外缺陷只記錄，撤回自身變更也須保留他人工作，不擴成資料修復、清理或部署。
- 採清楚、高效的最小主流程。優先框架原生能力及現有元件，不預建未用的抽象、接口、狀態、配置、相容分支、回退或重試。新增概念須有需求與現有能力不足的依據；不為罕見情況拖慢常用操作。若確需犧牲效能，先說明概率、影響、維護成本並取得確認。
- 避免重複請求／查詢／運算、無界處理、過度序列化、主執行緒阻塞、無意義重渲染與一次載入過多資料。只清理本次直接修改範圍內確認無用的內容、import 及引用；不做無關重構、格式化或全倉改名。保留相容程式與他人未提交變更，每條差異應能對應需求。

## 能力歸屬與架構

- 先定義產品問題、服務的使用者／業務、資料與狀態權威、能力歸屬及模組層級，再決定名稱、入口、配置與宿主，不因首個呼叫者方便而決定歸屬。
- 共用簽核協調、補償、通知、調度、權限、配置與採集放在職責相符的既有共用層；業務只持有自身規則與處理，沿穩定契約接入。共用核心不得反向依賴業務頁面、Controller 或專用實作，也不一律移到中央服務或建立 Common 大雜燴、插件框架與機械轉發接口。
- 調度與單次業務執行分開，優先既有統一調度；執行有界且可重試。背景租戶、身份與資料範圍來自已驗證的持久化任務或明確契約，不依賴當前 HTTP／登入，也不以預設身份補足。
- 驗收檢查依賴方向、權限／配置入口、啟用條件、資源生命週期及失敗隔離；停用單一業務不得連帶停用其他使用方。既有歸屬錯誤僅在授權範圍修正，其他列可追蹤事項，不以改名或消除例外宣稱完成架構治理。

## 程式碼與相容性

- 依實際 manifest、編譯器、框架、依賴與既有慣例，使用已支援的最新穩定語法；不為語法升級工具鏈、框架、依賴或啟用 preview。新語法不能改變契約、序列化、反射、ORM 翻譯、求值時機或資源語義。
- 沿用專案與語言命名；無更嚴格規範時，型別及成員用 PascalCase，參數與區域變數用 camelCase。公開成員改名前先查相容影響。
- 所有新增的類別、介面、enum、delegate、建構式、方法、屬性、欄位及其他宣告均須有符合語言慣例的文件註解；修改未註解的既有宣告時補上。可呼叫成員交代用途、參數、回傳、相關例外與副作用；不可空泛或誤導。關鍵／複雜邏輯註解解釋規則與原因，不重述語法。

## 資料、安全與發布

- 正式／生產及各廠區正式資料庫預設只讀；寫入、刪除、結構遷移、初始化或測試資料須有明確的目標資料庫、操作類型與精確範圍。遷移功能不授權補造測試資料；可回滾、測試前綴或功能未上線不等於寫入授權。只操作點名資料，驗證優先用既有資料，不足先確認來源及範圍。
- 資料庫操作優先用本機可用的資料庫 MCP；確認服務不可達或目標不在清單並記錄證據後，才允許一般直接連線備援，避免多套無用連線。專案若要求特定 MCP 專用入口，遵守其限制，不以此一般備援規則繞過。
- 伺服器執行身份、權限、範圍與狀態校驗；前端顯示／停用不算授權。不得在來源碼、文件、測試、截圖或日誌加入密鑰、Token、私鑰、連線字串或個資；診斷需遮蔽。
- PhoneRecord 發布允許由 AI 工具執行。當使用者在目前任務明確要求發布正式版本或授權完整發布流程時，AI 可完成版本號調整、編譯、測試、發布打包、建立與推送版本標籤、觸發 GitHub Actions，以及建立／上傳／發布 GitHub Release，不需再要求使用者手動執行同一發布步驟。單純修改程式碼或提交／推送分支不自動視為發布授權。優先使用倉庫既有的 `.github/workflows/release.yml`，正式發布由 `vX.Y.Z` 標籤觸發，標籤版本必須符合 `cpp/product_version.h`，且提交必須屬於 `main`。發布前須完成適用驗證；只使用既有安全儲存的發布憑證與簽章金鑰，不在對話、原始碼、日誌或產物中暴露其內容。正式 Release 須具備 exe、SHA256 與簽章更新資訊，確認 Actions 成功、資產完整及 latest 指向後才宣稱發布完成。失敗時可在原授權範圍內診斷與修復，但不得強制改寫既有公開標籤或覆蓋已發布版本；必要時使用新版本。發布授權不延伸至修改實體話機、本機個人設定、正式資料庫，或自動更新／重啟使用者正在運行的程式。此規則是使用者於 2026-11-05 明確授權的專案差異，取代共用來源中「發布僅由開發人員操作」的限制；其他資料、安全與授權規則保持適用。

## 驗證與資源生命週期

- 每項來源碼變更須成功編譯直接受影響專案，並按風險執行相關測試與靜態檢查。修復優先重現原錯誤的真實路徑或最小整合測試；聚焦通過不等於全套通過。既有失敗記錄命令、原始錯誤與阻礙，仍執行可行的範圍驗證，不順手修無關問題。
- 不依 API 名稱推定行為；不熟悉或版本相關 API 須按實際版本查官方文件／原始碼／反射或執行證據。檢查真實配置，包括自動關閉、連線池、交易、逾時及 DI／作用域生命週期。
- 連線級暫存表、會話變數、交易鎖、游標等須在同一物理連線完成建立、跨查詢使用及釋放；同一 ORM 物件或 Open／OpenAsync 不證明連線保持。每個 await 前後都核對上下文、連線與交易，不預設同步與非同步共享它們。
- 保存並用 using／await using／可靠 finally 釋放 IDisposable、IAsyncDisposable、鎖及作用域句柄；依賴資源先釋放，所屬上下文後釋放，異常路徑同樣清理。驗證無連線／Handle 洩漏、未結交易、鎖或暫存殘留。
- 資料存取依風險檢查 SQL、參數化、查詢次數與真實授權。編譯／ToSql 成功只證明靜態形態，不能代替真實請求、資源或交易驗證；不加靜默降級、重複查詢或多套回退掩蓋根因。
- 環境、服務、帳號、權限或資料不足時列明未驗證項、原因及必要驗證步驟；結果標為「程式碼修復完成，運行時待驗證」，不宣稱整項功能完成。不為測試擅寫正式資料。

- 所有新增／修訂的功能、架構、資料、遷移、優化、計劃與設計 QA 均包含「國際化與多語言交付」章節，明列客戶端、既有交付語系、預設語言、選擇來源、缺漏翻譯行為及驗收；不自行增減語系或延後翻譯。不適用也須說明理由。

- 必要業務／技術文件與實作同次更新，規劃與已實現行為分開；按專案規範保存方案與掃描結果，不以提交訊息取代權威說明。
