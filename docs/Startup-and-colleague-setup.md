# 啟動適配檢查與同事端設定

## 自動檢查與自動改設定的邊界

有效設定、非離線、自動事件模式且本機監聽成功時，程式啟動後會自動執行本機檢查、必要登入及唯讀話機適配檢查。匹配時可顯示已準備接受測試通話；不會自動修改話機設定，也不會為了檢查發送 Start／Stop。

啟動檢查若遇到通話，會延後至通話與錄音 session 結束、靜默約 20 秒後再執行；即使停用定期健康檢查，仍可完成這次延後檢查。登入或讀取失敗、設定不匹配等結果會正常顯示，不會因為自動檢查就當成適配成功。外部觸發模式仍保留原本的手動適配檢查入口。

適配只驗證當下的可讀設定，不證明雙向聲音、通話錄音命令權限或網路錄音品質。仍需一通實際測試，核對錄音時間及雙方聲音。接通開頭少字的現象仍在實機驗證中。

## 同事如何設定

1. 將程式放在同事電腦可寫入的固定資料夾，首次開啟填寫同事自己的話機 IP／Web 連接埠、話機 Web 帳號密碼、本機 IP 及儲存位置。不要將自己的 `config.ini`、cookie、通話目錄或已生成設定腳本直接交給同事使用。
2. 儲存後退出並重新開啟，讓連線設定生效。自動適配檢查若顯示不匹配，在「連接設定」按「一鍵設定話機」。
3. 確認沒有通話，核對預覽的目標與修改欄位，按「是」才套用。完成後回讀驗證並重查，程式保持運行。
4. 撥接一通約 20 秒的測試電話，掛斷後回放，確認錄音檔及雙方聲音。

一般使用者直接透過一鍵設定完成；介面已移除腳本產生入口，既有命令列工具保留供維護用途。

腳本只調整既有支援的 Network 錄音模式、支援 codec、目標位址／控制連接埠及接通／掛斷回呼，保留其他表單欄位；有既有回呼衝突、無權限或不支援的韌體表單時不宣稱成功。修改前會保留目前 Windows 使用者可解密的備份，失敗時嘗試回復並驗證。備份及登入資料受 Windows 使用者範圍保護，不能假設換人換電腦後可直接解密。

## 帳號權限

此處的權限是話機 Web 管理端權限，與 Windows 是否為管理員分開判斷。

| 帳號能力 | 實際影響 |
|---|---|
| 不能登入或不能讀取錄音管理頁 | 程式不能完成必要驗證，無法依目前自動流程啟動錄音。 |
| 能讀設定，但不能寫錄音及回呼設定 | 可以檢查；一鍵設定仍需由有權限者操作。設定寫入收到 401／403 或登入頁時，套用會失敗並回報權限原因。 |
| IT 已設定好，帳號可讀錄音頁，且 Start／Stop 可執行 | 日常自動錄音可使用此帳號；不必每次重做設定。 |
| 帳號不能執行 Start／Stop | 即使適配檢查顯示設定匹配，目前程式仍無法用此帳號自動啟停錄音，需要 IT 提供具備必要權限的帳號或調整話機角色。 |

不能僅以「一般使用者」或「唯讀」角色名稱推定 Start／Stop 的實際權限；需依該話機與韌體的實際回應驗證。腳本不會繞過話機權限。

## 驗證範圍

新增啟動自動檢查及通話中延後、通話結束後自動續檢的合成 loopback 整合測試。另沿用既有引導／三語 UI 檢查及一鍵設定的預覽、套用、回復、寫入拒絕及腳本生成測試，均不連線正式話機或修改同事設備。實機部署與同事帳號權限仍需目標環境驗收。

2026-11-04 隔離 x86 build 成功；產品回歸 14/14、引導檢查 7 項、設定腳本檢查 8 項均通過。產物與證據位於 `docs/probe/auto_compat_20261104/`。設定測試新增指定 exe 的參數，其結果雜湊也改為取實際指定的 exe；本次證據中原本仍引用預設路徑的雜湊已按實際測試 build 修正，測試斷言及通過結果未變。

使用者手動退出後已完成本機替換、備份及 SHA256 核對。重啟後自動檢查回傳 `ready`，本機、登入、錄音模式、codec、位址／連接埠及兩個回呼檢查均通過；`runtime_verified=false`，實際通話與聽感驗收仍為 pending。未手動觸發適配檢查，也未改寫話機設定。安裝的本機 build SHA256 為 `abf7411faaaaa39bea82895baf4ef8ba9c3a03d8ffb581e854b2aec6e3a63d3f`。

## 國際化與多語言交付

客戶端為 C++ Windows 桌面程式，保留簡體中文、繁體中文、English，沿用既有語言預設與使用者選擇來源。自動檢查使用既有適配狀態、診斷及翻譯 key，沒有新增使用者介面字串或缺漏翻譯；設定腳本仍依生成時的介面語言呈現既有提示。各語系的切換、缺漏與版面沿用既有引導測試驗證。
