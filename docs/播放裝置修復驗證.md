# 新電腦播放裝置修復

## 問題與範圍

2026-11-05 使用者提供的 2.7.4 診斷截圖多次出現 `PLAYBACK_FAILED operation=open mm_result=2`。Windows 的 `MMSYSERR_BADDEVICEID` 表示輸出裝置識別碼無效；截圖無法區分沒有可用裝置、停用／拔除裝置、預設映射失效或遠端音訊環境。

播放器仍使用 Windows waveOut 與原始 8 kHz、16-bit、單聲道 PCM。先開啟預設映射，只有回報 `MMSYSERR_BADDEVICEID` 才依現有裝置索引嘗試最多 32 個，成功即停止。正常預設播放不增加裝置掃描；其他錯誤不啟動掃描。成功恢復時記錄 `PLAYBACK_DEVICE_FALLBACK`，各次嘗試記錄索引與結果，不記錄通話資料。

開啟、播放、暫停、停止、拖曳及串流失敗由介面顯示原因與技術碼，關閉失敗的播放工作階段，允許重新按「播放」。檔案不可讀／不完整、裝置不可用／占用及格式不支援各有處理建議。清理失敗另記錄 `PLAYBACK_CLEANUP_FAILED`，不覆蓋原始錯誤。

未改寫錄音、音量、Windows 預設裝置、話機或連接設定。若 Windows 沒有可用輸出，須先連接／啟用喇叭或耳機，不能靠程式建立硬體。修改僅在本機工作區，尚未正式發布；隔離測試 exe 保留產品版本 2.7.4。

## 驗證

- 直接受影響的完整 C++17／Windows x86 產品隔離編譯成功。
- `pwsh -File tools\Test-AudioPlayer.ps1 -WithOutput`：重現錯誤 2，驗證有效索引恢復、零裝置、32 個上限、恢復後重試、其他錯誤不掃描、原始 PCM 不變、各進度單位、暫停／拖曳／重播與句柄／header 釋放。實際 Windows 音效輸出驗證使用合成靜音 WAV，涵蓋正常映射及注入映射錯誤後的真實裝置播放。
- `py -3 tests\desktop_workflow.py --exe tmp\playback-build\PhoneRecord.exe --output docs\probe\playback_20261105\workflow`：原生桌面播放控制、三語檔案錯誤及修復後再播、loopback 模擬通話與背景健康檢查。
- `py -3 tests\localization_smoke.py --exe tmp\playback-build\PhoneRecord.exe --output docs\probe\playback_20261105\localization`：三語各 408 個資源、即時切換及既有輸入／說明驗證。

本機實際輸出與測試注入證明修復路徑可運行，不能代替使用者新電腦的實際驅動、預設映射與通話人聲驗收。狀態：程式碼修復完成，新電腦運行時待驗證。

## 國際化與多語言交付

原生 Windows 客戶端沿用簡體中文、繁體中文及 English，首次依 Windows 選擇，後續依 `<config>.ui` 與側欄切換。六個新增錯誤 Key 集中於 `ui_resources.hpp`，三語均提供內容；缺漏沿用既有缺少文案提示。技術日誌與協議值保持穩定。桌面驗收覆蓋三語錯誤顯示、技術細節及失敗後控制停用／重新播放；裝置原因由原生模擬驗證，實際新電腦的三語裝置錯誤版面仍待現場確認。
