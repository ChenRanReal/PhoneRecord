# 自動更新與 GitHub Release

本文件描述 2.7.0 的已實作流程。首次使用更新功能須手動安裝具備更新能力的版本；舊版 2.6.x 不會自行取得此功能。原始碼與 Actions 設定完成不等於已發布正式安裝檔，正式檔案以 GitHub Releases 為準。

## 日常操作

側欄「軟體更新」提供檢查、下載及重新啟動並更新。更新偏好即時保存，不需保存話機連線草稿，也不重新初始化錄音服務。

| 項目 | 行為 |
|---|---|
| 自動檢查 | 預設每 6 小時，可選關閉、1、6、12、24 小時 |
| 啟動 | 自動檢查開啟時，啟動約 60 秒後第一次檢查 |
| 常駐／睡眠 | 收至托盤持續排程；睡眠後超過期限只補查一次，不補跑所有錯過次數 |
| 手動檢查 | 側欄更新頁與托盤右鍵選單均提供；關閉自動檢查仍可使用 |
| 更新氣泡 | 獨立開關，預設開啟；不受既有錄音／收至托盤氣泡開關影響 |
| 重複提示 | 同一版本只自動請求一次氣泡，去重紀錄跨重啟保存 |
| 托盤標識 | 驗證新版後疊加藍色向上箭頭；提示文字列出版本；關閉氣泡仍保留 |
| 查看更新 | 點更新氣泡或托盤的更新項目，顯示更新頁；沒有自動退出或自動安裝 |
| 系統限制 | Windows 可能抑制氣泡，或把托盤圖示放入隱藏區；程式不強制變更 Windows 的圖示可見性 |

背景只查詢固定公開倉庫 `ChenRanReal/PhoneRecord` 的最新正式 Release，不使用使用者的 GitHub 憑證。只接受 `vX.Y.Z` 標籤；數字比較版本，不安裝同版、舊版、預覽版或附件不完整的版本。403／429 後保守冷卻一小時，手動操作也不繞過。網路失敗保留之前驗證過的新版標識，不影響錄音健康狀態；成功查證沒有新版或版本撤回時清除標識。

背景更新有獨立工作執行緒，不使用話機 HTTP 佇列，也不觸碰話機設定。網路連線、發送與接收分段逾時為 5 秒；回應讀取有整體期限，JSON／簽章／下載大小均有上限；退出時取消請求並回收執行緒。`--offline` 完全停用更新網路與安裝。

## 下載、安裝與復原

1. 使用者點「下載更新」後，以 HTTPS 將固定名稱附件下載至隨機暫存目錄。
2. 用程式內嵌 RSA 公鑰驗證更新資訊的 SHA-256／PKCS#1 簽章，再驗證完整 exe 的簽署大小與 SHA-256。未設定公鑰、簽章或摘要錯誤時拒絕安裝。
3. 下載完成後，由使用者點「重新啟動並更新」並確認短暫服務中斷。通話、錄音、錄音收尾、已收到而尚待處理的通話事件、背景話機操作或檔案分析期間不可安裝。
4. 對更新候選與新通話接納分別上鎖，防止定時檢查撤換暫存檔或新通話插入安裝判斷。進入已確認的安裝退出階段後，新通話事件會收到 HTTP 503，新控制會話不再建立。此時的短暫不可錄音空窗與一般退出重啟相同。
5. 由目前受信任程式的暫存副本擔任輔助程序，使用限制的繼承 handle 清單，先驗證目前父程序路徑、簽章、暫存檔及殘留備份，再向主程序確認準備完成。主程序正常退出後才替換 exe。
6. 備份命名為 `PhoneRecord.exe.update-backup`；新版以原本的絕對設定路徑、背景啟動參數重新啟動，透過繼承事件回報原生視窗已建立。回報前不接納新通話，以免啟動失敗復原時截斷新錄音。這是程序啟動確認，不代表真實話機端到端錄音已驗收。
7. 新版 60 秒內未回報或提早結束時，輔助程序還原舊版並重新啟動。若目錄權限、檔案占用或復原失敗，保留備份與更新結果供人工處理，不覆蓋既有備份。

只替換程式與更新暫存檔；不改寫設定、DPAPI 登入快取、語言偏好、開機啟動註冊路徑、錄音、CSV 台帳或歷史名稱。錄音、通話及分析中的程式不會因發現新版而重啟。

正常退出會清除未安裝的下載。已交給輔助程序的暫存資料由新版或還原後的程式清理，只刪除指定目錄內四個已知更新檔案，不遞迴掃描或刪除其他內容。強制關機或程序被終止可能留下暫存目錄，不能把殘留目錄當成已安裝成功。

## 發布端：一次性設定

簽章公鑰在 `cpp/update_public_key.hpp`；私鑰不得寫入 Git、文件或日誌。

```powershell
# 初始化或重用目前帳戶的 DPAPI 加密私鑰，只將公鑰寫入原始碼。
./tools/Initialize-UpdateSigning.ps1

# 一次性上傳 Actions Secret；需既有 Git Credential Manager 登入與 PyNaCl。
# 若不希望全域安裝 Python 套件，可將套件裝於自訂目錄並使用 -DependencyPath。
./tools/Set-UpdateSigningSecret.ps1
```

私鑰以目前 Windows 帳戶的 DPAPI 加密保存於 `%LOCALAPPDATA%\PhoneRecord-Publisher\update-signing.dpapi`。上傳腳本從標準輸入向 Python 傳遞私鑰，只以 GitHub 提供的公鑰加密後寫入 `UPDATE_SIGNING_KEY` Secret，輸出僅包含 Secret 名稱與更新時間。私鑰檔受目前帳戶與電腦保護，應依組織的金鑰保管流程備份；若遺失，不可隨意重建公鑰，否則既有客戶端會拒絕未來更新。

初始化腳本會拒絕自動旋轉已設定的公鑰。換電腦或帳戶時需按金鑰保管流程恢復原金鑰，不能只複製 DPAPI 檔後假設可解密。

## 每次發布：由開發者觸發

`cpp/product_version.h` 是版本權威，C++ 日誌與 Windows exe 版本資源共同使用。發布之前更新版本、完成驗證，將來源碼合併至 `main`，再推送對應版本標籤。

```powershell
# 僅由開發者在確認版本與來源碼後執行；以下是首次版本範例。
git tag v2.7.0
git push origin v2.7.0
```

`.github/workflows/release.yml` 使用 Windows runner，依序：

1. 核對穩定版標籤、版本權威、簽章 Secret，確認發布 commit 屬於 `main`。
2. 編譯 x86／C++17／靜態 CRT 程式，執行原生更新回歸與合成錄音測試。
3. 用 Actions Secret 簽署固定 LF、UTF-8 無 BOM 的 `update-manifest.txt`；簽署腳本核對 Secret 公鑰、編譯資源與標籤一致。
4. 建立 Release 草稿，附上 `PhoneRecord.exe`、`PhoneRecord.exe.sha256`、`update-manifest.txt`、`update-manifest.sig` 四個附件，全部成功且回讀存在後才發布。

工作流程使用固定 commit SHA 的官方 Actions，正式發布工作序列化；發布較舊的版本時不把它指定為最新版本。既有 Release 不會被自動覆寫；上傳失敗保留草稿，查明原因後由開發者處理。不要以舊標籤重新指向不同原始碼。Releases 的「Source code」壓縮包不是客戶端更新檔。

`.github/workflows/ci.yml` 對 `main`、`codex/**` 分支及 PR 執行編譯、原生更新測試與合成錄音測試；此流程不發布 Release，也不取得簽章 Secret。互動式桌面與氣泡驗證另於本機進行，不假設 GitHub runner 有可互動桌面。

## 開發與驗證

```powershell
cmd /c cpp\build.bat
./tools/Test-Updates.ps1
$env:PYTHONIOENCODING='utf-8'
$env:PYTHONUTF8='1'
py -3 tests\update_ui_smoke.py --output docs\probe\updates\ui
py -3 tests\product_smoke.py --output docs\probe\updates\product
py -3 tests\desktop_smoke.py --output docs\probe\updates\desktop
py -3 tests\localization_smoke.py --output docs\probe\updates\localization
```

原生測試使用獨立測試 exe、臨時 RSA 金鑰與記憶體 HTTP 回應，覆蓋 .NET／CryptoAPI 簽章互通、版本比較、摘要／大小驗證、定時與睡眠補查、關閉與手動檢查、氣泡去重快取、限流、離線模式、竄改下載、新通話接納競態，以及實際輔助程序替換／啟動失敗復原。`PHONERECORD_UPDATE_TESTING` 只在該測試 exe 定義；正式 exe 沒有測試網路來源、測試信任根或測試環境變數的覆寫入口。

更新頁測試覆蓋三語、最小視窗、未保存的話機草稿、獨立偏好、托盤隱藏與 `TaskbarCreated` 訊息。真實 GitHub Release 的跨版本安裝、Windows 氣泡實際顯示與點擊、不同主題／DPI 的托盤標識、真正睡眠喚醒及實機通話仍需首次正式版發布後驗收；本機合成測試不能代替這些驗收。

## 國際化與多語言交付

客戶端支援簡體中文、繁體中文、English，沿用 `cpp/ui_resources.hpp`。預設語言由既有 Windows UI 語言規則選擇，之後使用 `<config>.ui` 保存的使用者偏好；新增更新狀態與設定均同時交付三語。缺漏翻譯沿用既有資源檢查，不用翻譯文字作為版本或狀態識別值。

Release 說明保留發布者原文，頁面明確標示，不自動翻譯；沒有說明時顯示對應語系的空白說明提示。版本、簽章格式及診斷代碼維持穩定；最近檢查時間按本機時間顯示。Windows 托盤提示與通知顯示限制由系統管理。
