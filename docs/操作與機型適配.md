# PhoneRecord 操作、欄位與機型適配

產品名稱建議統一使用 **PhoneRecord（通話錄音工作台）**。名稱直接說明用途，也不綁定特定電話品牌；目前保留既有目錄、執行檔名稱及資料格式。
程式內「說明與適配／帮助与适配／Help & devices」提供相同主題的簡體、繁體及英文說明，離線可閱讀。
首次交給其他人使用時，先閱讀 [快速上手](快速上手.md)，依電腦端與電話端對照逐步完成設定；可選用空白的 [config.example.ini](../cpp/config.example.ini)。

## 一般操作

1. 在連接設定填寫話機、本機位址、連接埠及保存目錄。選取欄位即可閱讀下方用途說明。
2. 依下表區分話機網頁埠、TCP 錄音控制埠、事件埠與 UDP 音訊範圍。
3. 保存連接參數，無通話時按左下「退出程式」並重開。右上 X 預設只收至托盤，並未重啟。確認本機與話機健康燈，執行適配檢查。
4. 接通正常電話，自動起錄；掛斷後完成 WAV，狀態回到待機。錄音資料支援程式內播放、暫停及拖曳進度。
5. 有異常時查看診斷中心代碼與建議，複製／匯出報告。訊號通過仍須聽音核對雙向內容。

## 每個欄位的用途

| 欄位 | 設定鍵 | 用途與限制 |
|---|---|---|
| 話機 IPv4 | `phone_ip` | 電話本身的網路位址，從話機網路狀態取得，用於網頁認證及事件來源核對 |
| 話機網頁埠 | `phone_port` | 話機管理網頁的 HTTP 埠，通常為 `80`；1–65535 |
| 登入帳號 | `phone_user` | 可存取話機錄音頁面的網頁帳號，與 SIP 分機號碼分開 |
| 登入密碼 | `phone_pass_dpapi` | 話機網頁密碼；保存時依目前 Windows 帳號加密，換電腦／帳號應重填 |
| 本機可達 IPv4 | `advertise_ip` | 空白時自動帶入；填完話機 IP 並離開欄位後依路由更新未手改的建議，保留已保存／手動值。控制回應以此告知 RTP 目的地 |
| TCP 控制埠 | `control_port` | 接收話機錄音 Start／Stop 請求，預設 `10000`；須與話機「錄音伺服器埠」一致 |
| 事件接收埠 | `hook_port` | 接收通話建立／結束 HTTP 回呼；建議 `18080`，可設 1–65535，須與話機 Action URL 一致 |
| 外部觸發 | `hook_port=0` | 明確勾選後停用本機 HTTP 事件服務，由既有外部控制器起錄；一般自動錄音不勾選 |
| UDP 起始埠 | `udp_port_start` | 音訊範圍起點，預設 `20000`；每個活動會話獨占一埠 |
| UDP 結束埠 | `udp_port_end` | 預設 `20100`；須不小於起點，兩者差最多 1000，話機須能存取該 UDP 範圍 |
| 音訊空閒逾時 | `idle_timeout` | 已開始收到音訊後，多久沒有有效 RTP 就收尾，2–120 秒；與最長通話時長及 TCP 首幀等待分開 |
| 錄音保存目錄 | `record_dir` | 保存 WAV、品質 sidecar 與台帳；相對路徑依設定檔目錄解析，變更不自動搬移舊檔 |
| 關閉視窗時 | `close_action` | 系統托盤、工作列最小化或直接退出；前兩者繼續錄音，保存後立即生效 |
| 健康檢查 | `health_interval` | 空閒時每 30／60／120／300 秒或僅手動；通話中暫停話機 HTTP，掛斷後至少等 20 秒；保存後立即生效 |
| 托盤氣泡通知 | `tray_notifications` | 預設 `0` 關閉；勾選後為 `1`，控制收起與開始錄音的氣泡，保存後立即生效，不影響錄音與日誌 |
| 開機啟動（背景） | Windows 目前使用者啟動項 | 預設關閉；勾選／取消立即生效，不用按保存。登入後托盤執行，雙擊圖示開啟；移動 exe 後關閉再開啟以更新路徑，不隨設定檔複製 |
| 介面語言 | `config.ini.ui` 的 `language` | 首次依 Windows 選擇；側欄選簡體、繁體或 English，即時更新並獨立保存；不提交未保存連接欄位、不重建錄音會話 |

五個連接埠輸入框限制半形數字及 1–65535，負數、小數、文字與超出範圍的貼上整筆拒絕。編輯過程可暫時清空，保存時仍須合法。
`0` 的外部模式由勾選項表達，保留舊設定檔的相容性；輸入框本身維持正整數。TCP 控制與事件埠不得相同。

連接與目錄保存後需重啟，避免改變運行中連線的一半設定。語言即時生效，關閉、氣泡及檢查頻率保存後立即生效。
預設設定為 `cpp/config.ini`；語言偏好為 `cpp/config.ini.ui`，自訂 `--config` 時使用該檔名加 `.ui`。

## 本機 IPv4 預設值

首次空白時從 Windows 本機網卡資訊帶入；已有話機 IPv4 時，依 Windows 到話機的最佳路由選擇來源位址。只讀本機介面與路由，不向話機或外部網站發送偵測封包。背景執行，不阻塞設定畫面。

已保存或手動輸入的位址保留；自動帶入僅是尚未保存的建議，不修改運行配置、話機設定或防火牆。沒有可用位址、預設網卡同優先序或多個無閘道網卡無法判斷時留白，讓使用者手填。填好話機 IP 並離開該欄位後，會更新未經手改的建議；過期結果不覆蓋新欄位。

驗證包括位址篩選、路由優先、歧義留白、保留手動／已存值、背景完成順序與退出回收；採合成介面及原生欄位通知測試。另以本機 Windows 新建隔離設定視窗確認實際自動帶入，不輸出本機位址、不寫入配置，也不連實體話機。

## 更換事件埠，釋放 8080

8080 可替換，預設為 **18080**。需改用其他埠時請同步兩端，勿將事件埠填到話機的錄音伺服器埠。

以下為通用模板，將占位文字替換成自己的本機可達 IPv4 及事件埠：

```text
通話建立：http://<PC_IP>:<EVENT_PORT>/event?ev=est
通話結束：http://<PC_IP>:<EVENT_PORT>/event?ev=end
```

1. 無通話時確認新埠未被占用，網路允許話機存取該 TCP 埠。
2. 修改程式事件埠，保存、退出及重啟，確認新埠監聽。
3. 讀取話機全量 Action URL，僅修改兩條錄音回呼的埠。保留原路徑、參數及公司其他 URL。
4. 回讀比對，確認目標兩條及其他欄位。不要以 HTTP 200 單獨判定保存成功。
5. 本機／話機檢查後，再以一通真實電話驗證事件、RTP 及新 WAV。

內建埠說明只顯示通用模板，不顯示使用者的實際位址，也不直接修改話機。
維護工具 `tools/migrate_event_port.py` 預設僅產生唯讀計畫；`--apply` 才執行兩欄變更，並要求新程式已監聽、健康正常及無活動錄音。原設定以目前 Windows 帳號加密留作回復。

## 品牌及型號的適配狀態

| 分類 | 型號／組合 | 證據與狀態 |
|---|---|---|
| 已驗證組合 | Fanvil X3S，硬體 V1.1，韌體 2.4.7.9.1 | 已有 C++ 真實通話及話機來源 WAV 收尾證據 |
| 可嘗試，尚待本工具驗證 | Fanvil X4、X5S、X6、X7、X7C、X210、X210i、XU 系列 | 列於廠商錄音文件；須依具體韌體驗證認證、起錄、控制、雙向音訊及收尾 |
| 尚未適配 | 其他品牌／其他認證及錄音協議 | 先依下方能力矩陣比對，可能需新增觸發／認證適配器或解碼器 |

候選機型依 [Fanvil 錄音設定文件](https://www.fanvil.com/Uploads/Temp/download/20191225/5e0335a76c55c.pdf)；文件中的廠商錄音能力不代表本工具已驗收。
廠商指南亦提到 G.722，本工具目前解碼範圍為 **PCMA／PCMU**。見 [Fanvil 功能指南](https://www.fanvil.com/downfile.aspx?id=5171)。

## 新機型必須符合的能力

| 層次 | 目前契約 | 新機型適配及驗證 |
|---|---|---|
| 起錄事件 | 通話建立／結束 HTTP GET 回呼，`ev=est/end` | 可產生對應事件，或由外部控制器起錄；只在通話建立後觸發 |
| 網頁控制 | 既有 nonce／MD5 會話、錄音狀態頁及 Start／Stop CGI | 逐一比對認證、狀態值與切換語義；不同協議在 `phone_client.hpp` 新增適配，不直接套用 X3S 行為 |
| TCP 協議 | `RecordStartRequest`／`RecordStopRequest`，同一會話的 `id` 一致 | 比對欄位、編碼、分隔及關閉方式；相關接收位於 `recording_core.hpp` |
| UDP 目的地 | 讀取 Start 回應的 `server/port`，向分配埠送 RTP | 實際看到有效 RTP；TCP 連入與控制回應不等於收到音訊 |
| 音訊 | PCMA／PCMU、8kHz，RTP PT 8／0，話機提供雙向混音 | 分別說話確認雙向內容；其他編碼需新增解碼及品質／播放契約測試 |
| 網路 | 話機可達本機 IPv4、控制／事件 TCP 與音訊 UDP | 核對網卡、路由、防火牆及來源驗證；保留既有企業設定 |
| 收尾及恢復 | 掛斷、Stop、無音訊／空閒逾時、正常退出 | 驗證 WAV 標頭、時長及品質；連續來去電、長通話及斷網恢復另列驗收 |

SIPREC、SIP INFO 或 G.722 等需要新增相應適配或解碼；不能只依「有 SIP／錄音功能」認定相容。
新增機型應留下品牌、完整型號、硬體與韌體、設定對應、控制／RTP 證據及真實雙向通話結果，通過後才列為已驗證。

## 一鍵設定話機

連線檢查僅驗證網頁；話機端仍須設定錄音目的地與通話回呼。在「連接設定」按「一鍵設定話機」，核對預覽後按「是」套用；寫入前加密備份，寫入後回讀並重查，程式保持運行。已有其他公司用途的目標回呼會停止。說明見 [話機自動設定](話機自動設定.md)。

## 一鍵適配檢查

在連接設定或說明與適配按「適配檢查」。程式核對已保存並啟用的運行配置，逐項讀取錄音管理及 Action URL；必要時先登入。檢查為唯讀，不修改話機、不撥號、不發送 Start／Stop。

檢查項目包含本機監聽／儲存、網頁認證、支援的欄位介面、啟用錄音、Network、PCMA／PCMU、錄音伺服器與本機設定一致，以及通話建立／結束回呼。結果與修正建議不列出實際 IP 或回呼值，可直接複製適配報告。這是介面辨識，並非自動取得品牌型號。

「設定需修正」請依對應欄位修正；「介面尚待適配」表示目前軟體不認識此介面，不能直接推論電話硬體不支援；「無法判定」則先處理連線、權限或登入問題。未保存／未套用變更需先保存並退出重開；通話中延後檢查。

「可進行通話驗收」只表示讀取的設定符合。接通約 20 秒，雙方輪流說話後掛斷，再播放最新檔確認雙向內容。只有檢查後的新通話完成來源、控制、RTP、WAV 與訊號證據，才會提升鏈路結果；人工試聽仍不可省略。

## 國際化與多語言交付

簡體中文、繁體中文、English 各有完整資源，包含選單、欄位、按鈕、狀態、診斷建議及說明內容。
日誌代碼、協議欄位與既有資料格式保持穩定，Windows 系統對話框及原生系統按鈕依 Windows 語言。
程式與文件為 UTF-8 無 BOM，缺少資源會顯示明確標記，不以其他語言悄悄代替。

本機 IPv4 的空白提示、欄位說明與首次引導同步提供三語；沿用 Windows 首次語言與左下使用者選擇，缺漏資源仍明確標示。語言切換只更新提示，不重跑偵測、不改寫位址。
