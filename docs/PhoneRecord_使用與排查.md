# PhoneRecord 2.3 使用與排查

## 直接啟動

雙擊 [Start-PhoneRecord.cmd](../Start-PhoneRecord.cmd)。新版位於 `cpp/PhoneRecord.exe`，檔案內容版本為 `2.4.0`。
首次使用請先讀 [快速上手](快速上手.md)；exe 可單獨啟動，沒有完整設定時開啟設定頁，讓使用者填自己的資料。程式內建三語首次設定對照及逐欄說明。
先看「运行概览」，必要時按「本机检查」與「话机检查」。介面給出明確代碼及下一步，不必先找人讀原始日誌。

本機檢查不訪問話機，檢查配置、本機 IPv4、監聽狀態、錄音目錄寫入及剩餘空間。
話機檢查會驗證會話並讀取錄音狀態；通話中不執行額外檢查，以保留話機處理錄音的能力。

新版可從連接設定產生自動設定腳本，流程、備份還原與缺少事件的判斷見 [話機自動設定](話機自動設定.md)。

## 真實通話操作

1. 無通話時啟動新版，確認控制埠實際監聽。自動模式另需事件埠監聽及話機驗證成功。
2. 接通電話並保持約 20 秒，觀察原有 Action URL 自動觸發。新版首頁已移除手動開始／停止，避免掛斷時誤發切換指令。
3. 看鏈路停在哪個階段，依下方代碼處理。話機 Start 是切換式動作，程式只按已建立通話事件起錄，不反覆補發。
4. 通話結束後，到「录音资料」播放、定位或「检查音频」。需確認新 WAV、RMS 變化與幅度門檻、真實話機來源。

`HTTP 200`、錄音圖示、`recordStatus=1`、控制會話建立都不能單獨計作成功。
Fanvil X3S 的 C++ 真實錄音已有既有驗證；新增功能不以此代替新版本的真實通話驗收。每台新裝置仍須完成上述試錄與雙向試聽。

## 適配檢查與首次設定

在「連接設定」或「說明與適配」按「適配檢查」，唯讀核對錄音欄位、啟用狀態、Network、編碼、目的地／控制埠及兩條回呼。檢查不改寫話機，也不發送測試起停。
結果逐項給出修正方向；介面不同列為尚待適配，讀取失敗列為無法判定。設定匹配後仍須以真實電話驗證音訊。說明與適配報告只列通用文字及檢查結果，不列實際 IP；其他技術日誌可保留排錯資料。
修改連接欄位後先保存，在無通話時按左下「退出程式」再重開；右上 X 預設只收至托盤。未套用變更與通話中會阻擋／延後適配檢查。

## 看懂概覽

| 階段 | 可以證明什麼 |
|---|---|
| 起錄觸發 | 收到事件，或使用者／設備控制要求啟動 |
| 指令 | 本程序完整送出 HTTP Start；外部觸發模式可能沒有此證據 |
| TCP 連入 | 本程序接受控制連線；不能反推沒有此行就是話機未送 SYN |
| 控制回應 | 成功 Start 的回應已完整發送，包含配置的 RTP 地址及分配埠 |
| 音頻到達 | 收到並驗證來源與支援編碼的 RTP，與檔案寫入分開 |
| 檔案寫入 | WAV 已建立並實際寫入 PCM |
| 品質檢查 | 文件完成後分析 RMS、peak 與完整秒變化；來源另行標示 |

「外部触发模式」表示 `hook_port=0`，本程序不接收 Action URL。可搭配既有外部觸發器；本機不再提供手動 Start 切換。
事件埠須與話機 Action URL 一致。只改本機埠不會自動修改話機；原有公司 IT URL 必須保留。

## 待機、健康燈與時間線

掛斷並完成收尾後，當前狀態回到「等待通话」，音頻卡回到「尚无音频」。上一通的鏈路保留在「上一通录音链路（历史结果）」中，下一通到來才重設，方便回查。
本機、話機各有獨立指示燈：綠色正常、紅色異常、黃色檢查中、灰色尚未檢查。失敗後重新檢查成功，對應燈會轉綠；上一通的錄音異常不會把成功檢查永久染紅。

預設空閒時每 60 秒檢查，可設 30 秒、2 分鐘、5 分鐘或僅手動。通話中不排程話機 HTTP，掛斷後至少等 20 秒再做背景檢查。
背景檢查不反覆登入；驗證失效時顯示異常，可在無通話時按「话机检查」重新驗證。
「最近运行事件」預設勾選「跟随最新事件」，最新列保持可見；可取消勾選閱讀較早事件。診斷中心在閱讀舊列時保留位置。

## 內建播放與聯絡人

在「录音资料」雙擊一列或按「播放」，聲音直接在程式內播放；底部提供暫停／繼續、停止與拖曳進度。播放不呼叫外部播放器，也不更改錄音檔。
`PLAYBACK_FAILED` 的 `mm_result` 可區分裝置或檔案問題；檢查音頻仍是另一個獨立操作。

撥出沒有姓名時只顯示號碼，不把 `s-xxxx-xxxx` 診斷指紋當姓名。顯示優先使用台帳與 sidecar，保留完整姓名、底線、逗號及引號；通訊錄中的 JSON Unicode 跳脫會解碼成中文。
本次不重新命名或改寫歷史錄音。無姓名的號碼若不在本機通訊錄，會維持顯示號碼。

## 關閉行為

「连接设置」中的「关闭窗口时」可選收至系統托盤、最小化工作列或直接退出。前兩者繼續自動錄音；側欄與托盤「退出程序」始終退出。
通話中退出仍有確認，避免未保存的通話被意外終止。托盤建立失敗時不會把視窗隱藏成無法找回的背景程式。
「顯示托盤氣泡通知」預設關閉，勾選或取消後保存即生效，不影響自動錄音、健康燈、時間線及日誌。

## 依代碼處理

| 代碼 | 優先處理 |
|---|---|
| `CONTROL_BIND_FAILED` | 看 TCP 埠是否由另一個專案實例占用；不要以視窗存在判定已監聽 |
| `EVENT_BIND_FAILED` | 看失敗埠與 WSA 錯誤。其他工具也可能使用 8080，由使用者安排釋放或協調兩端事件埠 |
| `LOCAL_IP_NOT_ASSIGNED` | 更新為話機可達的本機網卡地址，保存後無通話重啟 |
| `AUTH_*`／`PHONE_UNREACHABLE` | 無通話時按話機檢查，查看登入頁、明確 503 或連線失敗；不要直接改密碼 |
| `AUTH_SESSION_INVALID` | 無 nonce 且快取不被接受；無通話時關閉其他話機頁面，必要時從話機網頁退出後再檢查 |
| `CREDENTIAL_DECRYPT_FAILED`／`phone_pass_dpapi` 配置錯誤 | 換 Windows 帳戶／電腦後重新輸入密碼 |
| `PHONE_BUSY` | 明確 503，已有有限退避；暫停其他話機網頁操作後再試 |
| `CONTROL_NOT_OBSERVED` | 確認已接通及觸發來源，再以話機端或鏡像抓包區分 SYN 是否送出 |
| `CONTROL_NO_FRAME`／`CONTROL_NO_PAYLOAD`／`CONTROL_RESET`／`CONTROL_INCOMPLETE` | 查同一 `cid` 的 `CTRL_RX`、`CTRL_FRAME`、`CTRL_CLOSE`：位元組數、idle／EOF／分隔符、FIN／RST、尾端及時間 |
| `CONTROL_REPLY_FAILED` | 查 `CTRL_TX` 的 requested／sent bytes、WSA 錯誤與時間 |
| `RTP_NOT_RECEIVED` | 查分配 UDP、來源及 `RTP_INVALID`，不要反覆補發 Start |
| `UNSUPPORTED_CODEC` | 本工具解碼 PCMA／PCMU，由使用者核對話機編碼，不自動改配置 |
| `UDP_PORT_EXHAUSTED`／`SESSION_LIMIT` | UDP 無法分配或已有八個活動會話，先結束舊通話再檢查來源 |
| `WAV_*_FAILED`／`RECORD_DIR_NOT_WRITABLE` | 選擇可寫目錄並執行本機檢查，注意音頻到達與寫入失敗是兩件事 |
| `DISK_SPACE_LOW` | 可用空間低於 100 MiB，由使用者安排保存空間 |
| `LOG_WRITE_FAILED`／`LOG_ROTATE_FAILED` | 先複製記憶體報告，再檢查目錄權限或日誌鎖定 |
| `AUDIO_SUSPECT` | 固定音調、音量過低、過短或 I/O 異常，不算真實錄音成功 |

完整欄位、埠對應及機型要求另見 [操作與機型適配](操作與機型適配.md)。預設事件埠為 18080，可調整並同步兩條電話回呼；TCP 控制埠預設 10000。

所有代碼可在「诊断中心」搜尋；選一行顯示完整內容與建議，「仅警告与错误」可先縮小範圍。

## 診斷報告

按「复制报告」或「导出报告」。包含版本、當前觸發來源、各階段旗標、終身計數、RMS／peak、端口及最近 600 條遮蔽事件。
終身 RTP 與「本次是否收到 RTP」分開，避免前一通成功掩蓋下一通失敗。
技術日誌以毫秒時間、`cid`、會話指紋關聯，不輸出密碼、cookie、nonce 或通話姓名／號碼。

磁碟檔為配置目錄下的 `PhoneRecord.log`，約 2 MiB 輪替，另保留 `.1`／`.2`／`.3`。
介面記憶體保留 2,000 條，顯示最近符合條件的 500 條；報告不讀入舊版本日誌，避免帶入歷史憑據。

## 配置與資料位置

預設 `cpp/config.ini` 為扁平 `key=value`，不接受 `[phone]` 等段落。
相對目錄以配置所在目錄解析，`record_dir=recordings` 指向 `cpp/recordings`。
要查看先前 Python 歷史檔，可將目錄設為 自己的歷史錄音資料夾，保存後無通話重啟。
本次沒有搬動或改寫原有錄音。

連接與錄音目錄保存後重啟才套用，避免改變運行中連線的一半設定。關閉行為、氣泡通知與健康檢查頻率保存後立即生效。
舊明文 `phone_pass` 可讀；新版保存為目前 Windows 帳戶加密的 `phone_pass_dpapi`，舊鍵名不是 `phone_password`。
換帳戶或電腦應重填密碼。[Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。
原生介面不需要 8090；`ui_port` 僅為舊配置相容鍵。無週期性 calllog 同步，不會每幾分鐘再次登入話機。

## 命令列調試

```powershell
.\cpp\PhoneRecord.exe --config '.\cpp\config.ini'
.\cpp\PhoneRecord.exe --config '.\cpp\config.ini' --stop
```

開發隔離測試可用 `--offline --headless --run-for 15 --export-report <檔案>`，並先指定隔離埠與測試目錄的配置。
`--offline` 禁止訪問話機，其結果不能當作真實通話證據。

## 國際化與多語言交付

首次語言依 Windows 選擇；側欄可切換簡體中文、繁體中文與 English，立即套用於頁面、欄位、按鈕、狀態、建議與內建說明。
偏好保存在選定設定檔加 `.ui` 的獨立檔案，不提交未保存的連接欄位，也不重啟錄音或播放。
缺漏 Key 明確標記，技術代碼與資料格式保持穩定；系統對話框及系統按鈕按 Windows 語言。文件採繁體中文，程式與文件為 UTF-8 無 BOM。
