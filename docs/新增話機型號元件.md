# 新增話機型號元件

PhoneRecord 的錄音、事件與網頁流程讀取「目前話機型號元件」。已驗證的 Fanvil X3S 是第一個元件，也是沒有更強證據時的回退。新增一台使用相同網頁認證與 `RecordStart` 控制協議的話機時，只要新增元件，不必改核心判斷。

## 架構

核心保留這些共用能力：

- HTTP 傳輸、事件監聽、TCP 錄音控制、RTP／G.711、WAV、設定檔與 DHCP 配對狀態。
- `fanvil-nonce-md5` 這一種網頁認證的執行步驟。步驟使用的路徑、欄位、逾時與標記來自目前元件。
- `RecordStartRequest`／`RecordStopRequest` 這一種控制帧。命令名與來電欄位名來自目前元件。

元件負責：

| 能力旗標 | 內容 |
|---|---|
| `PR_CAP_EVENT_INGESTION` | 把回呼詞分成接通、掛斷、啟動完成、IP 變更 |
| `PR_CAP_DISCOVERY` | 依型號字串、HTTP 頁面或 `Server` 標頭給出分數 |
| `PR_CAP_CALL_METADATA` | 控制帧裡的本機號、對方號、方向與姓名欄位 |
| `PR_CAP_WEB_API` | 錄音頁、Action URL、Start／Stop 與 nonce 路徑 |
| `PR_CAP_AUTO_SETUP` | 一鍵設定可寫入的欄位與選項值 |
| `PR_CAP_DIRECTORY` | 通訊錄與通話紀錄 XML |
| `PR_CAP_NETWORK_RECORDING` | 是否接受網路錄音控制帧 |

契約在 `cpp/device_model.h`。內建 Fanvil X3S 在 `cpp/models/fanvil_x3s.hpp`，範本在 `cpp/models/sample_template.hpp`。範本沒有真實話機協議，也不會自動勝出。

## 如何被選中

啟動時程式載入兩個內建元件，再載入執行檔旁邊的 `plugins` 目錄，最多 32 個程式庫。Windows 讀 `*.dll`。缺少這個目錄不是錯誤。自動更新只替換 `PhoneRecord.exe`，不會清掉 `plugins`。

選擇順序：

1. `config.ini` 的 `device_model=` 等於已載入 id 時，固定使用該元件。既有設定檔沒有這個鍵，不需要改。
2. 該 id 不存在時維持 Fanvil X3S，並在日誌寫 `unknown_override`。之後不會再被頁面指紋換掉。
3. 沒有指定 id 時，取得分達到 **400** 的元件裡取最高分；同分取較大的 `priority`。
4. 沒有達標元件時使用 `fallback`，目前只有 `fanvil.x3s`。

Fanvil X3S 的自動分數：型號文字含 `x3s` 為 800，只含 `fanvil` 為 500，頁面含 `AURL_CallEstablished_RW` 為 460，同時含 `recordStatus` 與 `EnableRecord_RW` 為 440，`Server` 含 `fanvil` 為 420。範本的型號文字分數是 100，低於門檻，所以不會抢走既有使用者。

較弱的後續頁面不會推翻已經達標的選擇。通話進行中不重新比對。

同一 id 的外部程式庫會被略過，不能替換內建 Fanvil X3S。新話機請使用新 id。程式庫是本機程式碼，只從執行檔目錄載入。

## 新增一臺相同協議的話機

1. 複製 `cpp/models/sample_template.hpp` 與 `cpp/models/sample_template_plugin.cpp`。
2. 換上新的 id、顯示名稱、`priority`、回呼詞、頁面路徑、表單欄位與控制帧欄位。`auth_scheme` 維持 `fanvil-nonce-md5` 才會走現有網頁執行器；控制帧要沿用時加上 `PR_CAP_NETWORK_RECORDING`。
3. 在 `match` 裡只對這臺話機的明確證據給 400 以上的分數。不要對任意網頁給分。
4. 匯出：

```cpp
extern "C" PR_DEVICE_EXPORT const PrDeviceModelV1* pr_device_model_v1(void) {
    return yourModel();
}
```

5. 建置程式庫並放到 `PhoneRecord.exe` 旁邊的 `plugins`：

```bat
cl /nologo /std:c++17 /MT /LD /EHsc /utf-8 /D_WIN32_WINNT=0x0601 your_model_plugin.cpp /Fe:plugins\your.model.dll
```

6. 不改 `config.ini` 時，只有分數達標才會自動選中。想固定使用時加入 `device_model=your.model`，儲存後重新啟動。介面儲存會保留這個鍵；空白則不寫出，舊檔格式維持不變。

id 只允許英數、`.`、`_`、`-`，最長 64。元件裡的字串指標不可為 null；用不到的字串填 `""`。`record_status_regex` 若非空白，必須是可編譯的 ECMAScript，且有一個擷取群組。

不同認證或不同控制帧不能只填欄位。`auth_scheme` 設成 `none` 或其他名稱時，網頁登入與一鍵設定會回 `DEVICE_MODEL_UNSUPPORTED`，不會套用 X3S 的 nonce。那種話機需要擴充契約後再實作，不能假設現在的執行器會猜。

## 驗證

Windows：

```powershell
pwsh -File tools/Test-DeviceModel.ps1
```

測試涵蓋空證據回退、使用者指定、未知 id、Fanvil 頁面與型號文字、分數門檻、優先序，以及外部程式庫的載入、重複 id 與 Fanvil 契約字串。不連線話機，也不改 Windows 音訊裝置。

既有錄音、話機設定與事件測試仍是行為回歸。通過它們只代表合成話機上的契約沒變。

## 實機仍須確認

此元件拆分沒有在 Fanvil X3S 上重做通話。實機至少確認：登入與快取、一鍵設定兩條 Action URL、DHCP 的啟動／IP 回呼、接通後起錄、掛斷收尾，以及通訊錄讀取。自動選型只有在放入其他達標元件後才會離開 X3S。

## 國際化與多語言交付

此變更不新增介面語系，也不改既有簡體中文、繁體中文、English 資源與預設語言。`device_model` 是設定鍵，不是顯示文案。日誌與元件 id 維持英文穩定字串。缺漏的介面翻譯仍沿用既有標記，不會改用其他語言代替。本文件為繁體中文開發說明。
