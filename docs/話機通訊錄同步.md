# 話機通訊錄同步

桌面程式使用「連接設定」中已保存的話機位址、Web 埠、帳號及密碼，讀取話機的 `/contacts.xml` 與 `/calllog.xml`。無須安裝 Python 或另行執行同步腳本；不修改話機通訊錄、LDAP 或錄音設定。

## 操作與更新時機

- 正常模式登入成功並完成啟動檢查後，在閒置時自動同步；其後每五分鐘有一次閒置同步機會。通話結束後至少安靜二十秒才執行自動背景工作。
- 外部觸發模式也會在啟動後登入並讀取通訊錄。
- 「錄音資料」右上方的「同步話機通訊錄」可立即更新。通話、錄音、離線、設定尚待重新啟動或其他話機工作進行中時，按鈕停用。
- 通話開始時取消正在接收的背景通訊錄回應，避免繼續讀取第二份資料。連線建立有三秒上限，沿用話機要求的請求間隔；不保證所有網路階段均能立即中斷。
- 同步成功後刷新目前錄音清單，為原本只有號碼的紀錄補上可比對的姓名。已保存的原始姓名與自訂通話標題優先，歷史 WAV、台帳及 sidecar 不因同步被改寫。

## 姓名來源

新通話依序使用：話機錄音訊息中的姓名、`contacts.txt`、既有 `directory_file`（預設 `directory.json`）、自動同步的話機通訊錄、話機通話紀錄中的姓名。話機傳來的姓名若只是同一個電話號碼，仍會繼續查目錄。

同一位聯絡人的 `tel1`、`tel2`、`tel3` 都可比對；純電話號碼會忽略空白、連字號、括號及點號，保留開頭的 `+`。不猜測國碼、區碼、分機前綴或截取末幾碼。無比對結果時顯示原號碼。

通話紀錄只能補充話機已解析出的姓名；不會直接登入或查詢公司的 LDAP 伺服器。相同號碼以話機通訊錄為準，通話紀錄依回傳順序取第一個具名項目。

## 快取與失敗處理

同步結果儲存在設定目錄的 `.phone_directory.dpapi`，使用目前 Windows 帳號的 DPAPI 加密，綁定話機身分、Web 埠與帳號。固定 IP 使用設定的 IP；DHCP 使用設定的 MAC。人工目錄與同步快取分開，人工檔案不會被覆寫。請勿將這些個人資料放入版本控制或通用分發包。

兩份資料均成功讀取並解析才替換快取。斷線、權限不足、登入頁、無法辨識的空白結構、損壞 XML 或通話中斷均保留上次結果；成功回傳已知的空目錄結構則清除已刪除的同步項目。快取保存失敗時，本次姓名仍可使用，診斷頁提示檢查設定目錄的寫入權限。

診斷事件為 `DIRECTORY_SYNC_BEGIN`、`DIRECTORY_SYNC_OK`、`DIRECTORY_SYNC_FAILED`、`DIRECTORY_SYNC_DEFERRED`、`DIRECTORY_CACHE_FAILED`，只記錄狀態及筆數，不記錄姓名、號碼或 XML 內容。XML 使用 MSXML 6，禁用 DTD 與外部資源解析，限制 HTTP 回應與項目數量。[Microsoft MSXML 安全指引](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ms759188(v=vs.85))

## 國際化與多語言交付

客戶端為 Windows x86／x64 原生桌面程式。同步按鈕、完成、失敗、延後與快取提示使用既有中央三語資源：簡體中文、繁體中文、English。預設簡體中文，沿用既有介面語言選擇與保存來源；缺漏翻譯維持既有的明確缺漏提示。姓名依話機原文顯示，不翻譯，也不改寫電話號碼的儲存值。驗收包含三語按鈕、資源完整性與 Unicode 姓名。

## 驗證

以隔離編譯產物執行：

```powershell
py tests/directory_smoke.py --exe tmp/directory-x86/PhoneRecord.exe --output tmp/directory-tests-x86
py tests/directory_smoke.py --exe tmp/directory-x64/PhoneRecord-x64.exe --output tmp/directory-tests-x64
```

本次 x86／x64 均編譯成功，通訊錄整合測試各 9 項通過；既有錄音協議／媒體回歸 14 項、桌面流程 10 項與三語資源／切換檢查亦通過。

測試只存取 loopback 模擬話機及合成資料，涵蓋實際控制／RTP／姓名寫入路徑、來源優先序、多號碼、Unicode／XML entity、錯誤回應保留、加密快取與重啟、刪除、通話期間取消同步、啟動登入遇到通話後自動重試、離線與三語介面。實體話機的 XML 格式、帳號讀取權限、DHCP 換址及實際通話姓名顯示仍須現場驗證；模擬通過不代表實體話機驗收完成。
